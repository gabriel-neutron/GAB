7. **When an earlier read fails after `forget()`, it clears the promise of a later read.**
   - file: `src/shared/read/once.ts`:402
   - severity: nit
   - review agent's proof: `reading ??= read().catch(() => { reading = null; throw reason; })`. Code (lines 15-18, and 21-23):

    reading = null;
    throw reason;
  });
  ...
  forget: () => { reading = null; },

The catch handler writes `reading = null` with no check that `reading` still holds the promise of this read. `forget()` (line 22) clears `reading`, but it does not cancel the read that is in flight. src/shared/read/corpus.ts:39-43 calls `memory.forget()` and then `await reload()`. For this to occur, a read must be in flight when `refreshCorpus` runs, and that read must then fail. For example, two quick saves or acts (entity.$id.tsx:64, review.tsx:103, __root.tsx:96) each call refreshCorpus, and the first read fails. This is a narrow case. The fix is a small identity guard: keep the promise in a local const and clear `reading` only when `reading === thatPromise`. This fix does not change any other behaviour: a failure still clears the memory of its own read, and `forget()` still works.
