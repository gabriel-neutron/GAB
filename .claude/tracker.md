# Issue tracker configuration

This is the configuration that `to-spec`, `to-tickets`, `triage` and `wayfinder` expect to
have been handed to them. It replaces `/setup-matt-pocock-skills`, which is not installed
on this machine. **If a skill asks you to run that command, read this file instead.**

## Tracker

| | |
|---|---|
| Platform | GitHub Issues |
| Repository | `gabriel-neutron/GAB` |
| Access | the `gh` CLI |
| External PRs | **Not a request surface.** This is a single-operator project with no external contributors. `triage` covers issues only; do not discover or triage pull requests |

### Identity — this matters

This machine has two GitHub accounts. Everything in this repository must act as
**`gabriel-neutron`**, never as `Rovis91`.

Identity is pinned by a `GH_TOKEN` in `.claude/settings.local.json` (gitignored), which
overrides `gh`'s stored login unconditionally. **Never run `gh auth switch` or
`gh auth login` for this repository** — that reintroduces a machine-wide, forgettable
setting in place of a per-project guarantee.

Before any write to the tracker, confirm:

```bash
gh api user --jq .login    # must print: gabriel-neutron
```

## Label vocabulary

The skills use canonical role names. On this tracker the label strings are identical to
the canonical names, so no translation is needed.

**Category** — exactly one per triaged issue:

| Canonical | Label | Meaning |
|---|---|---|
| `bug` | `bug` | Something is broken |
| `enhancement` | `enhancement` | New feature or improvement |

**State** — exactly one per triaged issue:

| Canonical | Label | Meaning |
|---|---|---|
| `needs-triage` | `needs-triage` | Maintainer needs to evaluate |
| `needs-info` | `needs-info` | Waiting on the reporter |
| `ready-for-agent` | `ready-for-agent` | Fully specified; an AFK agent can take it |
| `ready-for-human` | `ready-for-human` | Needs human implementation |
| `wontfix` | `wontfix` | Will not be actioned |

**Structural:**

| Label | Meaning |
|---|---|
| `wayfinder:map` | Marks the single wayfinding map issue. Never apply it to anything else |

Every comment or issue body posted during triage must open with:

```
> *This was generated by AI during triage.*
```

## Wayfinding operations

The map is **one issue** labelled `wayfinder:map`. Its tickets are **child issues** of the
map. The map is an index, not a store: a decision lives in its ticket, and the map only
gists it and links.

Refer to a map or ticket by its **title**, never by a bare number, in anything a human reads.

### Find the map

```bash
gh issue list --label wayfinder:map --state open --json number,title
```

### Read the map and its decisions so far

```bash
gh issue view <map-number> --json title,body
```

### List the open tickets (the frontier candidates)

Child issues are queried from the map, not from a label:

```bash
gh api repos/gabriel-neutron/GAB/issues/<map-number>/sub_issues --jq '.[] | {number, title, state}'
```

### Create a ticket as a child of the map

Create the issue, then attach it. `sub_issues` takes the child's **internal id**, not its
number — resolve it first. **Use `-F`, not `-f`**: the endpoint requires an integer, and
`-f` sends a string, which fails with a 422.

```bash
gh issue create --title "<question>" --label "wayfinder:<type>" --body-file <file>
CHILD_ID=$(gh api repos/gabriel-neutron/GAB/issues/<child-number> --jq .id)
gh api repos/gabriel-neutron/GAB/issues/<map-number>/sub_issues -F sub_issue_id=$CHILD_ID
```

Every ticket carries exactly one type label: `wayfinder:research`, `wayfinder:prototype`,
`wayfinder:grilling`, or `wayfinder:task`.

### Blocking edges

**Native issue dependencies are supported on this repository — verified.** Use them; they
render the frontier visually in GitHub's own UI, so the frontier is visible without opening
the map. Same integer rule — `-F`, not `-f`:

```bash
BLOCKER_ID=$(gh api repos/gabriel-neutron/GAB/issues/<blocker-number> --jq .id)
gh api repos/gabriel-neutron/GAB/issues/<blocked-number>/dependencies/blocked_by \
  -F issue_id=$BLOCKER_ID
```

Read them back with:

```bash
gh api repos/gabriel-neutron/GAB/issues/<number>/dependencies/blocked_by \
  --jq '.[] | {number, title, state}'
```

There is no need for a `## Blocked by` body convention here — that fallback exists only for
trackers without native dependencies.

### Claiming a ticket

A session claims a ticket by **assigning it** before doing any work, so concurrent sessions
skip it. An open, unassigned ticket is unclaimed.

### The frontier

The open children of the map that are unblocked and unassigned — every blocker closed, no
assignee.

### Closing a ticket

Close it with a comment stating the decision, then add a one-line gist plus link to the
map's **Decisions so far** index. The decision text itself stays in the ticket — never
restate it on the map.

## Publishing specs and tickets

- `to-spec` publishes the spec as an issue and applies `ready-for-agent`.
- `to-tickets` publishes one issue per ticket in dependency order, blockers first, applying
  `ready-for-agent`.
- Neither should close or modify a parent issue.

## Prior rejections

`triage` reads `.out-of-scope/*.md` to check whether a request has already been rejected.
That directory is tracked in this repository. The standing exclusions are in
`docs/prd.md` §5 — treat that list as authoritative and as a first-rank deliverable:
anything on it is `wontfix` by construction.

## Domain vocabulary

Ticket titles, issue bodies and spec text use the project's terms as fixed in `docs/`:
candidate layer, evidentiary layer, proposal, claim, scoring, rating, rating origin,
dissent, review by exception, promotion, raw / GOLD, reliability (A–F), credibility (1–6).
Respect the decision register in `docs/decisions.md` for any area you touch.
